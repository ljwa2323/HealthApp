# HealthApp 产品规格

## 1. 核心用户问题

现实中的健康数据往往按医院、科室和时间被切碎。患者就诊时通常无法完整提供既往资料，医生只能依赖患者记忆和当前一次检查。

HealthApp 的核心价值不是再做一个健康问答，而是让患者逐渐形成一份持续积累的个人纵向健康记录。

## 2. MVP 页面

### 首页

展示：

- 当前主要健康问题
- 正在服用的药物
- 最近异常指标
- 即将需要关注的复查事项
- 最近新增记录

### 时间轴

所有事件按真实临床时间排列。

支持过滤：

- 检验
- 影像
- 诊断
- 用药
- 门诊
- 住院
- 手术
- 生命体征
- 患者自述

同一天多个事实应折叠为一个事件，避免时间轴过长。

### 上传记录

支持：

- 拍照
- 相册
- PDF
- 手动输入

处理状态：

1. 文件已上传
2. OCR 完成
3. 文档类型识别
4. 结构化抽取
5. 需要确认
6. 已进入时间轴

### 趋势

第一阶段重点支持：

- 血压
- 心率
- 体重
- 血糖
- HbA1c
- 肌酐/eGFR
- 血脂
- 血红蛋白
- 肝功能

用户点击任意点可以回到原始报告。

### AI 助手

助手不直接读取全库，而通过工具查询：

- `get_timeline`
- `get_observation_series`
- `get_medication_history`
- `get_condition_history`
- `get_source_evidence`
- `find_data_gaps`

所有回答都应显示用了哪些时间范围和记录。

## 3. 典型用户流程

### 第一次使用

1. 创建个人档案
2. 连续上传过去的重要检查
3. 系统自动识别并排序
4. 用户只处理低置信度冲突
5. 首页生成基础纵向摘要

### 就诊前

用户点击生成就诊摘要：

- 当前主要疾病
- 当前药物
- 最近 12 个月关键异常
- 重要手术/住院史
- 过敏史
- 关键指标趋势

同时生成二维码或 PDF，供医生快速查看。

### 就诊后

患者拍照上传新报告，系统自动合并到原有时间轴，而不是创建孤立的新文档。

## 4. 交互原则

- 医学原文必须一键可见
- AI 结论永远不能隐藏依据
- 低置信度结构化结果必须允许用户修改
- 不要求用户理解复杂医学编码
- 时间轴默认按事件发生时间
- 异常提示应克制，避免把每个超参考范围指标都等同于疾病

## 5. 后续能力

完成可靠数据层后，再逐步增加：

- 可穿戴设备接入
- Apple Health / Health Connect
- 医院电子病历导入
- FHIR 接口
- 家庭成员健康档案
- 慢病管理路径
- 随访提醒
- 医疗知识 RAG
- 个体化风险预测
- 就诊前自动摘要
