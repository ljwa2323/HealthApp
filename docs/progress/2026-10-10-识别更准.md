# HealthApp 阶段进度报告（识别更准）

日期：2026-10-10
分支：`dev/yexiaohan`（本地开发分支，尚未合并主分支）
负责人：叶潇涵

## 一、本轮目标
推进"添加记录识别更准"主线：上传 + OCR 环节用真实引擎替换占位实现，并把识别结果整理成结构化数据，为后续 AI 助手和病程管理打基础。

## 二、已完成

### 1. OCR 引擎替换
- 原占位 OCR（Demo）替换为 **RapidOCR**（PP-OCRv4 模型，ONNX 运行时），本地离线运行、零成本
- 附带头文件识别、图片预处理、自检式文本行排序

### 2. 识别准确率（已量化）
- 使用**GT 人工标注评估体系**（真实照片 + 逐字抄录基准 GT）
- 字符错误率 CER：无预处理基线 **47.6%** → 全测试集 **35.2%**；通过清晰度门槛的图片 **CER 17.0%**（即识别准确率约 83%）
- 另对 20 张网络真实化验单建立扩展测试集（详见第 4 点）

### 3. 清晰度检测
- 对低分辨率、模糊、过暗的图片，前端弹窗提示"建议重新拍摄"（不强制拦截，用户仍可上传）

### 4. 规则版字段级提取 + 前端人工审核
- 把 OCR 混杂输出整理成**结构化字段**：项目名 / 数值 / 单位 / 参考范围 / 偏高偏低判定 / 置信度
- 方案：坐标重建 + 检验项目词典 + 正则解析（不依赖 LLM，零成本）
- 前端配套**人工审核面板**：每条结果可确认 / 修改 / 排除，低置信度项标黄提示"建议核对"，并保留 OCR 原文供对照
- 20 张网络化验单评测：**单列/列表式报告（肝功能、甲功、尿常规等）字段准确率 69%～100%**；双列/多列表格（血常规、生化全套）容易出现结构性错位

## 三、已知限制
- 规则版提取对**双列/多列表格**存在列错位：根因是 OCR 把左右两列识别进同一文本块，坐标信息在 OCR 层失效，规则方法无法重建
- 解决方向（下一阶段）：本地表格结构识别（PP-Structure 类）或轻量 LLM（30B 内）做表头语义归位

2. 多列表格结构识别（上述限制的专项解决）
