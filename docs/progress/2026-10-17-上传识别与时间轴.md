# HealthApp 开发进度汇报

> 2026-10-17 · 阶段性汇报

## 总体进度

把散落的检查单 / 影像照片上传后自动识别、结构化，按**单据日期**整理进时间轴，方便自己和后续的 AI 助手使用。

## 已做完的事

1. **上传与质量检查**：支持拖拽 / 选择图片上传；上传时自动判断是"文字型检查单"还是"纯影像"（X 光 / CT 片子这类照片）
   - 纯影像：直接保存原图、不走 OCR，进时间轴「影像」板块
   - 文字型：进入识别流程
2. **识别链路（双通道）**：RapidOCR 本地识别 + GLM 视觉模型直接读图提取，输出结构化字段；支持 9 类文档分类（检验、影像报告、用药、门诊、住院、手术、生命体征、症状、其他）
3. **OCR × AI 交叉核对**：AI 提取的每一项与 OCR 原文比对，给出"一致 / 与 OCR 不一致 / OCR 未读到"三种提示，供人工核对
4. **叙述型文档处理**：AI 先判断该文档要不要分条；不分条的（如出院记录、整段病程）直接展示**可编辑原文**，用户改完再决定是否加入时间轴
5. **自定义结构录入**：用户可自己设计"一条记录"的字段结构（如 六点体温 / 八点体温 / 十二点体温…），支持填写和选择类型，可"自动填入"已识别数据
6. **时间轴**：
   - 按**单据日期**排序（新在上、旧在下），识别不出日期的让用户选择年月日
   - 「全部 / 检验 / 影像 / 用药」板块
   - 贯穿竖线 + 节点圆点，左侧标注日期
   - 删除按钮移到每条记录的头部（"查看"旁边）


## 遇到的问题与解决

- **手写体温单 RapidOCR 严重乱码**（0/O、1/l 混淆，5.jpg 实测只"识别出一列"）→ 改用 GLM 视觉模型直接读图，字段准确率明显提升（20 张图评测约 92%）
- **纯影像被误判**：暗色片子照片曾被误报"太暗"、被误跑 OCR 识别成"检验单" → 增加文字 / 影像分流（影像跳过 OCR 只存原图），阈值单独校准
- **时间轴按上传时间排不对** → 改为按单据日期排序；图上识别不出日期的，让用户手动选择


## 还没解决的

- 手写体温单**逐格精确识别**很难（目前数值是概括式，无法逐格对应）
- AI 判断"分条记录 / 整体记录"偶尔可能不准，目前没有加**没有手动切换开关**
- vital（生命体征）等类记录在时间轴筛选里没有单独板块，只在「全部」里


## 下一步

- **识别部分**：前端文字遮挡等细节优化
- **AI 助手 / 健康咨询模块**：基于时间轴数据回答"这段时间血糖怎么样""某次检查为什么异常"这类问题，回答带证据来源；
