# HealthApp 开发进度汇报

> 2026-10-23 · 阶段性汇报

## 总体进度

这周完成 **AI 健康咨询模块**跑通：基于患者自己的时间轴结构化数据回答健康问题，回答带证据引用、置信度评分和数据缺口提示。

## 已做完的事

1. **聚焦型上下文结构设计**：不做向量库 RAG（数据量小、临床指标有明确概念名可精确匹配），而是把时间轴数据预聚合成一份 JSON 喂给 LLM：
   - `series`：按临床概念分组，每条带趋势（上升/下降/平稳）和变化幅度
   - `active_medications`：折叠成"当前在用药"视图，不逐次罗列处方
   - `data_gaps`：三层降级——字典命中时列出"该查但没查"的指标；字典未覆盖时只列实际观测到的概念；无数据时直说
   - `data_quality_issues`：自动检测缺日期、缺单位、缺参考范围、OCR 噪声
2. **双模型管线**：GLM-4-Flash 做意图路由（判断问题属于肝功/肾功/血糖/泛问等主题，提取时间窗），DeepSeek-V3 做最终回答。路由免费、生成按量付费
3. **回答接线**：FastAPI 路由 + SSE 流式输出，前端边收边显示
4. **证据引用校验**：LLM 回答里每个数值标注 `[fact_id]`，后端回查这些 ID 是否都在本次上下文里，抓到幻觉引用直接报
5. **置信度评分**：根据命中指标数、有日期数据占比、数据缺口数、幻觉数综合算一个 0.1~0.95 的分数，分档给不同提示语（高分"仅供参考"，低分"建议补充以下检查"）
6. **低置信度回答策略**：不允许 LLM 只说"材料不足咨询医生"，必须先说看到了什么异常、再列缺什么检查、最后具体建议补什么报告
7. **多对话持久化**：SQLite 建 conversations 表，左侧栏改成对话列表 + 搜索框 + 新对话按钮，切换对话加载历史，刷新不丢

## 遇到的问题与解决

- **置信度虚低（0.28）**：临床 panel 字典里"ALT"和"谷丙转氨酶"被当成两个独立指标检查，患者数据里是英文缩写能匹配 ALT，但中文项匹配不上就报了 6 个假缺口，每个扣 0.02~0.03 把分数压到底 → 把 panel 改成别名组结构，同一指标的不同写法（中英文缩写、全称）合并为一项，任一字段命中即算已检测
- **LLM 低置信度时只会说"材料不足"**：prompt 加了结构化要求，强制按"看到什么异常 → 缺什么 → 建议补什么"三段式回答，同时把 data_quality_issues 塞进上下文让 LLM 主动指出"这个数值没日期，建议补一下"

## 还没解决的

- 病理报告这类叙述型文档 OCR 后字段内容为空（有记录但无文字值），AI 能看到条目名但读不到结论
- 置信度公式还是粗调的，权重（基础分、series 加分、gaps 扣分）需要更多真实问答数据校准
- 流式接口目前非流式端点在自动存对话，SSE 流式端点的消息持久化刚接上还没压测

## 下一步

- **图片识别优化**：叙述型文档（病理报告、手术记录）的字段提取准确率；OCR 噪声清理；缺日期/缺单位的自动补全提示
- **AI 助手优化**：置信度公式调优；多对话搜索体验；测试更多真实问答场景找幻觉和误报；考虑加用户反馈按钮（回答有用/没用）来迭代 prompt
